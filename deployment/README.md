# Model conversion and Arduino artifacts

`training/train_final.py` trains the final binary network and calls `deployment/tflite_export.py`. The converter preserves inference outputs when removing training-only GaussianNoise/dropout, exports float32 and full-int8 TFLite, and compares predictions on validation. Int8 calibration uses only training features without augmentation (up to 200 class-balanced examples). The configured final fit uses V3 and FFT512. The binary entry point uses B003: CNN1D8/16/32, k3, MFCC13/Mel32, batch128, LR0.005. `training/train_final_three_class.py` exports T001 with k7, MFCC13/Mel40 and dropout0.50.

Outputs under `results/final_model/<timestamp>/`: `best.keras`, `eva_inference.keras`, `eva_float32.tflite`, `eva_int8.tflite`, `deployment.json`, conversion metrics, histories and manifests. Set `REUSE_RUN` in the final-training entry point to resume conversion without retraining; config and dataset fingerprints must match.

Open `deployment/prepare_arduino_reference.py` in Spyder and run F5, or run it as a module from the root. Set RUN_FOLDER to a specific completed final run or leave None for the latest. WAV_PATH selects a reference clip; None selects an EVA validation clip. It writes C++ model arrays and reference audio/MFCC arrays under that run's `arduino_reference/`.

Copy the generated `.h`/`.cpp` model arrays into the inference sketch you intend to build. The three test sketches also require `reference_data.h/.cpp`; `eva_continuous` uses these for its optional reference check. These files contain learned weights or recorded audio and are ignored by Git. The main `firmware/eva_bracelet` sketch implements INT8 inference, vibration, cancellation and BLE.

The TFLite model contains the CNN, not MFCC extraction. Input is `[1,55,C]`, where C is13 or20. Class order is eva/non_target for binary and eva/noise/unknown for three classes; deployment.json records the exact configuration. The C++ MFCC dependency must reproduce deployment.json settings. Quantize int8 inputs with its recorded scale/zero point and dequantize outputs. Existing generated artifacts were not moved or regenerated by the folder reorganization.

The generated reference_data.h records reference_fft_length. Copy it together with the matching model and reference arrays: the firmware passes this value to EVA_MFCC. Historical artifacts remain FFT256; changing defaults does not retrain or convert those weights. If the grid selects a different architecture or MFCC count, update train_final.py and the fixed firmware input/front-end before exporting.

Named firmware candidates and validation-selected thresholds are documented in firmware/README.md. Generated weights and recorded PCM/reference arrays remain local: their .cpp files are intentionally Git-ignored and must be copied with the matching headers from each run's arduino_reference directory. A fresh clone cannot compile these inference sketches until those artifacts are supplied.
