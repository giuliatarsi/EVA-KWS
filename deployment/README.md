# Model conversion and Arduino artifacts

`training/train_final.py` trains the final binary network and calls `deployment/tflite_export.py`. The converter preserves inference outputs when removing training-only GaussianNoise/dropout, exports float32 and full-int8 TFLite, and compares predictions on validation. Int8 calibration uses only training features without augmentation (up to 200 class-balanced examples). The current network is CNN1D 8/16, k5, MFCC13/Mel40, batch128, LR0.005.

Outputs under `results/final_model/<timestamp>/`: `best.keras`, `eva_inference.keras`, `eva_float32.tflite`, `eva_int8.tflite`, `deployment.json`, conversion metrics, histories and manifests. Set `REUSE_RUN` in the final-training entry point to resume conversion without retraining; config and dataset fingerprints must match.

Open `deployment/prepare_arduino_reference.py` in Spyder and run F5, or run it as a module from the root. Set RUN_FOLDER to a specific completed final run or leave None for the latest. WAV_PATH selects a reference clip; None selects an EVA validation clip. It writes C++ model arrays and reference audio/MFCC arrays under that run's `arduino_reference/`.

Copy the generated `.h`/`.cpp` model arrays into the inference sketch you intend to build. The three test sketches also require `reference_data.h/.cpp`; `eva_continuous` uses these for its optional reference check. These files contain learned weights or recorded audio and are ignored by Git. The future `eva_bracelet` model interface is not yet implemented.

The TFLite model contains the CNN, not MFCC extraction. Input is `[1,55,13]`; class order is eva/non_target. The C++ MFCC dependency must reproduce deployment.json settings. Quantize int8 inputs with its recorded scale/zero point and dequantize outputs. Existing generated artifacts were not moved or regenerated by the folder reorganization.
